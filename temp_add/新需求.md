## 忘记密码功能（优化版需求）

### 目标与范围
- 在现有登录功能基础上，新增完整的“忘记密码”流程，覆盖找回入口、身份校验、验证码验证、密码重置、会话安全处理与用户反馈。
- 适用于已注册用户，兼容用户名或邮箱作为唯一识别符（`identifier`）。

### 用户故事
- 作为用户，我在登录页点击“忘记密码”，输入用户名或邮箱后，收到验证码（开发环境通过后端控制台输出），用验证码验证身份，设置新密码并确认，返回登录页用新密码登录。
- 作为系统，我不泄露用户是否存在，限制验证码尝试次数，验证码过期后需重新申请，重置密码后吊销旧会话，提升安全性。

### 关键流程
1. 找回请求：用户提交识别符 → 系统生成 6 位验证码、记录有效期与尝试次数 → 在开发环境通过后端控制台输出验证码 → 返回统一“已受理”。
2. 验证码验证：用户提交识别符 + 验证码 → 系统校验成功后签发一次性短期 `resetToken`（仅用于密码重置）。
3. 重置密码：用户提交 `resetToken` + 新密码 + 确认密码 → 系统更新密码并吊销用户所有当前会话 → 返回登录页。

### 非功能性与安全要求
- 不暴露账户存在性：找回请求固定返回 `202 Accepted` 与通用文案。
- 验证码有效期：10–15 分钟；最多 5 次尝试，超限返回 `429`。
- 验证码与令牌存储：仅存储验证码哈希；`resetToken` 一次性、短期有效（例如 10 分钟）。
- 会话安全：重置成功后吊销用户全部 `sid` 会话，强制重新登录。
- 审计与日志：开发环境输出验证码；生产环境不输出验证码，仅记录事件。

### 验收标准
- 正常路径完成并可用新密码登录；旧密码失效。
- 错误码与状态码符合约定；验证过期、尝试超限、令牌失效行为正确。
- 开发环境能在后端控制台看到验证码；生产环境不泄露敏感信息。

### 接口设计
- 基础：路径前缀 `/api/v1/auth/*` 与现有风格一致（参考 `backend/internal/server/auth.go:30-35`）。身份字段统一为 `identifier`。

1) 申请找回
- `POST /api/v1/auth/forgot`
- Request: `{"identifier":"user_or_email"}`
- Response: `202 Accepted`，`{"status":"accepted","next":"verify"}`（不泄露是否存在）
- 行为：如用户存在，生成验证码、保存哈希/过期/尝试计数；开发环境通过控制台输出验证码。

2) 验证验证码
- `POST /api/v1/auth/forgot/verify`
- Request: `{"identifier":"user_or_email","code":"123456"}`
- Success: `200 OK`，`{"resetToken":"<opaque>","expiresAt":"<ISO>","next":"reset"}`
- Errors：
  - `400 {"code":"invalid_parameters","message":"bad request"}`
  - `400 {"code":"invalid_code","message":"Invalid or already used"}`
  - `410 {"code":"expired","message":"Code expired"}`
  - `429 {"code":"too_many_attempts","message":"Please request a new code"}`
- 行为：校验验证码哈希、有效期、尝试次数；成功签发一次性短期 `resetToken`。

3) 重置密码
- `POST /api/v1/auth/forgot/reset`
- Request: `{"resetToken":"...","newPassword":"pass123","confirmPassword":"pass123"}`
- Success: `200 OK`，`{"next":"login"}`
- Errors：
  - `400 {"code":"invalid_parameters","message":"missing fields"}`
  - `400 {"code":"password_mismatch","message":"Passwords do not match"}`
  - `401 {"code":"unauthorized","message":"invalid reset token"}`
  - `410 {"code":"expired","message":"Reset token expired"}`
- 行为：校验令牌有效与一次性使用；更新密码（bcrypt）；吊销所有用户 `sid` 会话（参考会话逻辑 `backend/internal/server/auth.go:63-69`）。

### 数据模型建议
- 新表 `password_resets`：
  - 字段：`id`、`user_id`、`code_hash`、`expires_at`、`attempts`、`max_attempts`、`used_at`、`reset_token_hash`、`reset_token_expires_at`。
  - 约束：`attempts <= max_attempts`；`used_at` 非空表示验证码已用；令牌一次性。
- 生成器：`CodeGenerator()` 与 `TokenGenerator()` 可注入，便于测试固定值。
- 日志策略：DEV 输出验证码；生产环境仅记录申请事件，不输出验证码。

### 前端交互与路由
- 登录页入口：在 `frontend/src/pages/LoginPage.vue:22-27` 区域增加“忘记密码？”链接，跳转 `'/forgot'`。
- 新增页面：
  - `ForgotPasswordRequestPage`：输入 `identifier` → 调用 `POST /auth/forgot` → 展示“已发送验证码（开发环境查看后端控制台）” → 跳转 `'/forgot/verify'`。
  - `ForgotPasswordVerifyPage`：输入 `identifier` + `code` → 调用 `POST /auth/forgot/verify` → 成功获取 `resetToken` → 跳转 `'/forgot/reset'`。
  - `ForgotPasswordResetPage`：输入新密码与确认密码 + `resetToken` → 调用 `POST /auth/forgot/reset` → 成功后跳转 `'/login'`。
- 路由挂载：沿用 `frontend/src/main.ts:14-15` 的模式新增上述路径。
- 交互细节：表单判空、密码一致性校验、统一错误提示；`resetToken` 仅在流程必要阶段短暂保存。

### 测试案例设计
- 后端集成测试（参考 `backend/internal/server/server_test.go` 风格）：
  - 正常流程：注册用户 → 申请找回（202）→ 使用固定验证码验证（200，返回 `resetToken`）→ 重置密码（200）→ 新密码登录成功、旧密码失败。
  - 错误与边界：不存在的 `identifier`（仍 202）、错误验证码（400）、过期（410）、超限（429）、密码不一致（400）、令牌失效或过期（401/410）。
  - 会话安全：重置后旧 `sid` 访问受保护资源（如 `GET /api/v1/session/me`）返回 401。
- 前端测试（Vitest + Vue Test Utils）：
  - 登录页存在忘记密码链接并能导航。
  - 请求页提交后调用接口并跳转验证页；错误时展示统一文案。
  - 验证页提交正确验证码返回 `resetToken` 并跳转重置页。
  - 重置页密码一致时成功并跳转登录页；不一致展示错误。
  - 端到端模拟：从登录页进入 → 三步完成 → 回到登录页用新密码登录（通过 `fetch` mock）。
